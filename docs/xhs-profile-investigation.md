## 已复现并修复的问题

1. **漏等已经发出的分页请求。** 旧代码到收到响应头才登记请求。现在从 CDP `requestWillBeSent` 开始追踪，到响应正文读取完才结束；在途请求阻止完成判定。
2. **慢请求被错误当作列表停滞。** 旧代码五轮没有新增 ID 就暂停，即使下一页还在传输。现在在途请求和页面加载不计停滞，不重复滚动，另设明确的 45 秒超时。
3. **旧结束标记永久生效。** 旧 `endReported ||= ...` 无法被后续 `has_more:true` 撤销。现在按请求开始顺序处理分页状态，新的明确响应优先，乱序返回的旧响应不能覆盖它。
4. **异步限流被误报完成。** 页面快照读取期间到达的 HTTP 429 原来可能被本轮完成判断遗漏。现在读取快照后再次检查，分批下载每次请求前也检查已经观察到的认证与限流。
5. **空卡片标题覆盖已有标题。** 原来带签名链接的 DOM 卡片会整体替换已有描述。现在链接与非空标题分别合并，标题单独补全也能更新队列。
6. **默认“小红书图片”覆盖真实标题。** 详情本身无标题时，源解析器给出显示占位文字。现在适配层保留标题来源；默认文字不覆盖主页真实标题，真正名为“小红书图片”的笔记仍可正常使用这个标题。已下载文件不做猜测性批量改名。
7. **缺结束标记阻塞所有下载。** 改为分批发现和保存；恢复继续按笔记 ID 合并、稳定编号，已保存文件验证后跳过。没有明确结束证据，当前批次全部保存也不能使任务变为整页完成。

保留 API 分页游标用于判断推进，重复游标不被当作持续进展；日志不记录游标原值、Cookie 或签名链接。对小红书响应异常、验证、取消仍保留原有停止边界。

## 验证与边界

本轮完整本地测试 571 项通过、8 项平台跳过、0 失败；原文校验 61/61 通过。主页界面、真实 Electron 主页分页与原有桌面下载链路均通过。新增真实 Electron 主页验证已接入 CI；本地结果不代替 GitHub CI 与最终安装包验收。

- 新增九项分页回归使用真实 `XhsBrowser.discover()`、模拟 CDP 事件和时钟。在已发布版本的浏览器实现上九项全部失败，在修复实现上通过，覆盖上述异步边界和标题合并。
- 队列回归覆盖首批保存后才继续下一页、3 → 121 → 151 的模拟分页、重复页、暂停与恢复、认证限制、稳定编号、标题来源与真实文件落盘。这里的 151 是测试数据，不是真实主页总数。
- 界面回归覆盖 121/9 和 151/151 尚未确认末尾的状态，只有收到结束证据的完成状态才显示 100%。
- `npm run test:xhs-profile-discovery` 使用真实 Electron、CDP、本机 HTTPS、滚动事件和文件保存验证完整批次流程。前两篇及图片落盘后才翻到第二页；第二页一篇重复、一篇新增，最终三篇按原顺序完成且图片字节完全一致。其页面和媒体是离线样本，不是线上主页数据。
- 流式保存期间，后到达的普通网络错误不能覆盖已经确认的登录或限流；不同分页请求的加载时间分别计算，保存本批次耗时不计入下一页的超时。两项独立复查发现的边界另有回归覆盖。
- 原媒体解析器和下载函数继续做原文校验；修改后的主页响应模块明确列为适配文件，只对未修改的 URL 与作者校验函数做原文检查。

10 月 28 日的匿名探测使用新临时用户目录访问给定主页，没有读取或改写已有账号和任务。两套程序均被小红书登录限制拦住：观察到 `user_posted` HTTP 200 / `code=-101`（无登录信息）、HTTP 461 或重定向 `/login`，发现均为 0，未绕过限制。当前网页仍使用 `user.notes`、`noteQueries`、`isFetchingNotes` 数组结构；登录页默认查询不构成结束证据。
