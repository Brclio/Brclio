### 内置更新代理

- Windows、macOS 和 Android 的新版本检查、校验清单和安装包下载可使用内置更新代理。
- 检测到系统代理时优先使用系统网络，不叠加内置代理；不修改系统代理设置。
- 在「通用设置 → 版本更新」或「关于 Brclio」中可临时关闭内置代理。两个入口保持同步，完全退出软件后重新启动默认恢复开启。
- 检查或下载期间锁定开关，避免中途切换网络。代理状态读取失败会明确提示，不能确认时不显示切换成功。
- 安装包仍只接受 Brclio 官方稳定版本，并继续执行大小、SHA-256 和各平台现有的安装验证。
- 内置代理在客户端运行，仅用于检查和下载更新。每次操作前刷新配置、对全部可用候选节点进行真实 HTTPS 测速，并使用成功节点中延迟最低的一条线路；操作结束或取消后关闭连接。
- 安装包和校验清单始终由 GitHub Releases 提供，客户端通过选定代理连续下载；Cloudflare 只维护网页、后台及代理配置，不中转或存储安装包。
- 代理节点连接与 GitHub 下载连接均保留客户端原生 TLS 证书和主机名校验，完整大小、SHA-256 和安装前复验继续执行。

### Brclio 主页与客户端管理

- [Brclio 介绍与下载主页](https://tools.brclio.com) 提供功能介绍、路径格式示例、平台安装说明及最新正式版下载。
- [综合客户端管理后台](https://tools.brclio.com/admin) 提供服务总览及独立的「更新与网络」模块，便于后续扩展其它客户端服务。
- 管理员可维护代理订阅，配置继续保存在现有私有数据仓库。客户端按需获取连接节点所需的配置，订阅原链接及服务端环境变量不随安装包发布。

### 安装与更新

- 可从软件中检查并下载安装更新，也可下载本页安装包覆盖安装，保留已有偏好。
- Windows 和 macOS 保留自动覆盖安装、设置保留及重新打开后的启动确认流程；Android 仍需系统确认覆盖安装，完成后尝试自动打开，受系统限制时可点击安装器中的“打开”。
- Android 版本同步为 0.1.9，versionCode 为 10，沿用项目既有发布签名。
- macOS 仍采用完整 ad-hoc 签名，尚未经 Apple 公证；Windows 安装器仍未配置公开 CA 发行签名。首次安装的系统提示与此前版本相同。
- 六个安装包与 SHA-256 清单由同一提交的发布流水线生成，全部构建与校验完成后才公开。
