## 下载工作流与输出的行为差异

| 项目 | 原版 | 当前 Brclio | 判定 |
| --- | --- | --- | --- |
| 解析后切换下载引擎 | 桌面引擎选择用于抓取与部分下载；图片代理及 ZIP 分段读取当前选择 | 下拉影响下一次解析；ZIP 读取笔记保存的 `note.engine`；原生保存走自己的网络路径 | 原版“换引擎重试已有结果”的工作流未完整保留 |
| 单篇视频默认 | 普通播放清晰度默认；原视频另有会员按钮 | 原视频候选排在同一下拉列表前面，默认先选原视频 | 有意改变入口和默认选择 |
| 原视频权限 | 会员接口重新解析并签发、复核票据 | 本地解析直接返回原视频候选，未迁入原会员体系 | 原权限工作流不同，不是额外去水印技术 |
| 单张实况 ZIP 失败处理 | 图片和 MP4 都成功才生成 ZIP | 共用批量导出器；图片成功、MP4 失败时仍可生成部分 ZIP 并报告失败 | 文件完整性/失败语义不同；不是静默声称完整 |
| 批量 ZIP 缺配对地址 | 已有静态图仍可进包，只有存在地址才加动态片段 | 所选混合 ZIP 会提前拒绝；可另选纯原图 ZIP | 更严格的完整性策略，但 UI 提前提示反而缺失，见 D5 |
| ZIP 预算 | 根据实际设备信息选择 128/256 MiB | 注入默认 Desktop/8GB，桌面归档固定走 256 MiB | 核心常量相同不等于运行限制相同 |
| 单图与目录保存 | 单篇主要通过代理取得 Blob 后保存 | 新增原生目录保存和完整笔记媒体/TXT/JSON 归档 | 路径、文件命名和失败边界不同 |
| ZIP/文案/元数据 | 图片常为 `01.jpg`、动态 `01-live.mp4`；单张实况包不附文案 | 使用实际媒体扩展名及不同目录/ZIP命名，实况 ZIP 额外附文案；单篇整篇归档含 JSON | 输出文件集合和整体 ZIP 字节不相同 |
| 实况配对散件 ZIP | 照片、MOV、README.txt | 照片、MOV，没有该 README；PVT ZIP 仍有说明文件 | 一项原版附加文件未保留 |
| 剪贴板提示 | 区分复制的是图片还是独立文件，并提示粘贴方式 | 大多统一提示“原图已复制” | 输出能力在，结果说明减少 |

依据：原版 `app.js:401,427,1268,1563,2096`；当前 `web/xhs.js:142,151`、`desktop/xhs/index.mjs:398,422,429,455`、`desktop/xhs/lib/source-download.js:23`。详细逐项来源见[单篇矩阵](../artifacts/xhs-source-audit-2026-11-02/single-note-matrix.md)。

下载本身按收到的媒体字节保存，没有二次压缩或转码；Store ZIP 也不改内部媒体内容。但同一笔记不代表两版一定选中相同视频候选或得到相同响应，不能据此承诺全部输出哈希相同。两版都从页面明确声明的原视频字段提取候选，都没有画面水印检测/消除能力；`sourceWatermark` 为未知，主页的 `watermarkFree:true` 是双方共有的来源标记，不能作为检测证据。

## Android、浏览器与独立产品功能

Android 的单篇文字解析、图片选择、原图保存/复制/分享、视频清晰度、实况 MP4/ZIP、文案和进度取消均有对应实现。默认解析由原版在线 Node/Python 改为本地取页与共享 JS 解析，Python 备用仍走在线接口；原视频由会员网页入口改为本地候选下载。图片格式处理有增强；前后台生命周期、参数上限和新分享结果处理存在 D3/D4 等差异。两边 Android 本来都没有桌面主页批量，不把它列为丢失功能。

当前 Android 还有两项需单独说明的完整性问题：

1. **纯实况 Python 补取不完整，已复现。** `web/bridge.js:99` 只在存在笔记级原视频且无地址时启动本地补取；纯实况笔记不触发，尽管相同页面的本地解析可取得动态片段。原版公开接口也可能过滤这类地址，因此这是当前新增补取能力的缺口，不称为原版已有功能的回归。
2. **整篇保存可能退化为只存文案，源码风险。** 声明有原视频但地址不可用时，`AndroidXhs.kt:163-169` 跳过空视频并添加文案，未校验不可用标记。本轮未执行 Android 原生保存来确认结果；原版 Android 也没有完全相同的整篇入口，不能直接归为原版回归。

网页版差异是明确的：原版能在浏览器解析并下载小红书笔记，有 HTTP/浏览器 Python、验证恢复、复制和 ZIP 流程；当前工具箱浏览器没有这条笔记获取链路，仍可做**本地实况生成、预览及导出**。原版的网页验证恢复仅在浏览器启用，不能误称其桌面单篇恢复功能在迁移时丢失。

原账号、会员、支付、头像数据、反馈系统、iPhone 快捷指令入口等未完整迁入；Brclio 使用自己的账号体系。原版编程课程/图书推广属于独立产品页面，不应误称下载教程。这些范围差异单独列出，**核心下载缺口的结论不依赖把会员支付或推广页面算进来**。

Android 及浏览器逐控件、输出、生命周期和外围模块对照见[平台矩阵](../artifacts/xhs-source-audit-2026-11-02/platform-matrix.md)。
